# FDE 学习 Day 5 复盘

## 学习时长

3～4小时。

## 今天学了什么

### 1. Git 与 GitHub Desktop

- 安装并登录 GitHub Desktop。
- 创建 `tutorial` 分支。
- 修改 `README.md` 文件。
- 使用 Commit 保存本地版本记录。
- 使用 Publish 将分支上传到 GitHub。
- 创建 Pull Request，走通一次完整协作流程。

学习流程：

```text
创建分支 → 修改文件 → Commit → Publish/Push → Pull Request
```

### 2. Python 错误调试

- 阅读错误类型、文件位置和行号。
- 使用 `print()` 查看变量内容。
- 使用 `type()` 检查变量类型。
- 发现 `input()` 返回字符串后，使用 `float()` 完成转换。
- 修复了字符串无法使用 `.2f` 格式化的问题。

调试思路：

```text
看报错 → 找行号 → 检查变量 → 确认类型 → 修改后重跑
```

### 3. assert 自动测试

- 测试整数面积 `100`，结果为 `45500`。
- 测试小数面积 `100.5`，结果为 `45727.5`。
- 故意写错预期结果，成功触发 `AssertionError`。
- 为断言增加中文错误提示。
- 修复预期结果后显示“所有测试通过”。

### 4. VS Code 断点调试

- 在循环累加代码处添加断点。
- 让程序暂停在第5行。
- 查看 `area`、`cost`、`costs` 和 `cost_per_mu`。
- 观察 `cost_per_mu` 从 `0` 变成 `60`，理解循环累加过程。

### 5. 正式代码作业

完成带自动测试的水稻成本计算器，并测试：

- 输入 `100`：预计总成本 `45500.00元`。
- 输入 `100.5`：预计总成本 `45727.50元`。
- 输入 `-10`：提示面积必须大于0。
- 输入“一百”：提示输入纯数字。
- 把正确预期值 `455` 故意改为 `450`：成功触发中文 `AssertionError`。

## 今天最容易卡住的地方

最明显的卡点是 VS Code 的断点设置和启动调试。快捷键不一致，加上断点图标不容易辨认，导致程序最开始直接运行结束。最后通过设置第5行断点并启动 Python 调试，成功看到变量变化。

## 问题是怎样解决的

- 不依赖不一致的快捷键，改用 VS Code 的运行和调试界面及命令。
- 先确认断点确实出现在第5行，再启动调试。
- 程序暂停后查看左侧变量，并单步观察累加器变化。

## 今日收获

今天第一次把“版本管理、调试、自动测试”连接成一套完整流程。代码不只是写完能运行，还可以保存修改历史、定位问题，并通过测试自动确认结果。以后使用 Codex 生成代码时，也可以先阅读，再运行、测试和验证，而不是只看最终答案。
