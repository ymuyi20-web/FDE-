# Day 10 农事操作日志数据契约

## 1. 这个模板记录什么

本模板记录育种基地里已经发生过的农事操作。

它不是评价表，也不是育种结论表。  
它回答的是：

> 某一天，某个材料、某个播期、某个小区，做了什么操作，由谁记录，是否需要复查。

## 2. 字段说明

| 字段 | 含义 | 是否必填 | 示例 |
| --- | --- | --- | --- |
| operation_id | 操作记录编号 | 是 | OP20260501001 |
| operation_date | 操作日期 | 是 | 2026-05-01 |
| material_name | 品种/材料名称 | 是 | 稻香A |
| sowing_batch | 播期 | 是 | 第一播期 |
| plot_id | 小区编号 | 是 | A-01 |
| operation_type | 操作类型 | 是 | 播种 |
| operation_detail | 操作内容 | 是 | 人工播种，行距 30cm |
| operator | 负责人/记录人 | 是 | 李工 |
| need_follow_up | 是否需要复查 | 是 | 是 / 否 |
| note | 备注 | 否 | 天气晴 |

## 3. 允许的操作类型

第一版先允许：

- 播种
- 施肥
- 打药
- 灌溉
- 除草
- 巡田
- 拍照
- 测量
- 收获

如果朋友后面有更多实际操作，比如“套袋”“挂牌”“取样”“测产”，再扩展。

## 4. 事实与判断边界

可以写：

> 已施用尿素 10 kg/亩。

不建议在日志里直接写：

> 这个材料表现很好。

前者是事实记录。  
后者是业务判断，应放在后续“评价/筛选”模块里。

## 5. 为什么要有负责人

负责人不是为了追责，而是为了可回溯。

当数据有疑问时，可以知道：

- 谁做的操作；
- 谁记录的；
- 后续要向谁确认。

这对田间试验非常重要。
