# Day 18 学习计划：用户反馈收集与版本迭代

## 今日主题

把“朋友试用后的意见”转化成 FDE 可以处理的迭代队列。

前面 Day15、Day16、Day17 已经做出了多个农业小原型。Day18 不继续堆功能，而是练习一个更接近真实交付的动作：收反馈、分类、判断优先级、形成下一版修改计划。

## 今日目标

- 做一个本地反馈收集页面；
- 能记录朋友对 Day17 施肥决策层原型的意见；
- 能把反馈分成 Bug、业务不符、新需求、体验问题、暂缓观察；
- 能导出 Markdown 反馈日志；
- 能根据反馈判断下一轮要先改什么。

## 今日文件

- `feedback_collector.html`：反馈收集与迭代看板；
- `FEEDBACK_LOG.md`：反馈日志模板；
- `FRIEND_FEEDBACK_MESSAGE.md`：发给朋友的反馈邀请话术。

## 学习阶段

### 阶段 1：理解反馈不是吐槽

FDE 不怕别人说“不好用”，真正怕的是反馈没有被记录、没有被分类、没有进入下一轮决策。

反馈要至少回答四个问题：

- 谁反馈的；
- 他说的是什么现象；
- 属于 Bug、业务不符，还是新需求；
- 下一步是否要改。

### 阶段 2：运行反馈收集页

打开：

`feedback_collector.html`

建议先点击“填入示例反馈”，观察页面如何把反馈放入不同类别。

### 阶段 3：自己录入 3 条反馈

可以模拟朋友反馈：

- “水稻地区分类还不够细”；
- “目标需肥量公式需要标注系数来源”；
- “页面顶部宽度和下方表单不一致”。

录入后观察：

- 类型统计；
- 优先级；
- 迭代建议；
- Markdown 导出结果。

### 阶段 4：形成下一版修改计划

把最高优先级反馈写入 `FEEDBACK_LOG.md`。

今天不要求马上改代码，重点是学会判断：

- 哪些必须马上改；
- 哪些要先问清楚；
- 哪些只是以后可能做；
- 哪些不应该做。

## 今日复盘问题

1. 为什么朋友说“这里不对”时，不能立刻全部照改？
2. Bug 和业务不符有什么区别？
3. 为什么反馈里要记录“原话”和“判断”两个部分？
4. 如果 Day17 收到 10 条反馈，你会先处理哪三条？为什么？

## 今日交付标准

- 能新增、删除反馈；
- 能看到反馈统计和迭代建议；
- 能导出 Markdown；
- 能说清楚一条反馈属于 Echo 还是 Delta。
