# Day 12 数据存储与重复提醒规则

## 1. 现在数据存在哪里

当前 Day11 表单使用的是浏览器本地存储：

```text
localStorage
```

你可以把它理解为：

> 当前浏览器给这个网页留了一小块本地空间，用来临时保存记录。

它不是服务器。  
它也不是自动写入 CSV 文件。  
它更不是多人共享数据库。

## 2. 本地存储适合什么

适合学习阶段和原型阶段：

- 验证字段是否合理；
- 验证手机录入是否顺手；
- 验证默认值是否减少工作量；
- 验证批量录入是否好用；
- 验证导出的 CSV 是否能接后续看板。

## 3. 本地存储的限制

本地存储有明显限制：

- 换电脑看不到；
- 换浏览器可能看不到；
- 清理浏览器数据可能丢失；
- 多个人之间不能自动汇总；
- 不能作为正式数据库。

所以它适合原型，不适合正式生产。

## 4. 什么时候需要服务器或数据库

当你想做到下面这些事，就需要后台或数据库：

- 多个人一起录入；
- 负责人之间共享记录；
- 管理员统一查看所有数据；
- 手机录完后电脑端自动出现；
- 数据不能丢；
- 要权限管理；
- 要长期保存；
- 要和 Day8、Day9、Day10 自动联动。

## 5. 后续可选存储方案

从简单到复杂，可以这样走：

| 方案 | 适合阶段 | 特点 |
| --- | --- | --- |
| 浏览器本地存储 | 原型 | 不用服务器，但只能自己看 |
| 复制 CSV | 小范围试用 | 最简单，但需要人工汇总 |
| Google 表格/在线表格 | 轻量试用 | 多人能汇总，但权限和格式要管 |
| 后台接口 + 数据库 | 正式产品 | 可多人协作、可长期保存 |
| 手机 App / 小程序 | 更正式 | 现场体验更好，但开发成本更高 |

## 6. 重复记录判断

第一版把下面这些字段都相同的记录视为“疑似重复”：

- 日期；
- 品种/材料；
- 播期；
- 小区；
- 一级操作类型；
- 操作内容；
- 负责人。

注意，是“疑似重复”，不是一定错误。

## 7. 为什么不直接禁止重复

因为农业现场可能真的存在重复操作。

比如：

- 上午上水一次，下午又上水一次；
- 同一天同小区补打一次药；
- 同一负责人对同一小区做两次巡田记录。

所以系统应该：

```text
发现疑似重复 → 提醒用户 → 用户确认后仍可保存
```

这叫软校验。
