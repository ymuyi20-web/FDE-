# Day 12 学习计划：数据存储边界与重复录入提醒

## 今天的目标

Day 11 做了田间手机录入表单。  
Day 12 要回答两个更像真实产品的问题：

1. 表单录入的数据到底存在哪里？
2. 如果用户重复提交同一条操作，系统应该怎么办？

## 你先记住结论

现在学习阶段，数据没有存到服务器。

它存在你当前浏览器的本地存储里，也就是 `localStorage`。

这意味着：

- 不需要开服务器；
- 不需要数据库；
- 不需要后台；
- 刷新页面后记录还在；
- 换一台电脑就看不到；
- 换一个浏览器也可能看不到；
- 清理浏览器数据后可能丢失；
- 真正交付给多人使用时，需要后台或数据库。

## 今天你要理解的 FDE 点

### 1. 原型阶段先验证业务流，不急着上服务器

现在最重要的不是“技术架构多完整”，而是：

- 字段是否符合现场语言；
- 录入是否足够省事；
- 批量操作是否好用；
- 默认值是否减少重复填写；
- 导出的数据能不能接 Day10 日志看板。

所以学习阶段先本地试运行就够了。

### 2. GitHub Pages 只能托管静态网页，不能天然保存多人数据

如果后面你把这个表单发到 GitHub Pages，它可以让朋友打开页面填写。

但注意：

> GitHub Pages 本身不会帮你把朋友填写的数据保存到你的电脑或后台。

朋友填写的数据只会留在他自己的浏览器本地。

所以正式使用时，要么：

- 复制 CSV 发给你；
- 上传 CSV；
- 接 Google 表格；
- 接一个后台接口；
- 接数据库。

### 3. 重复录入不能直接粗暴禁止

同一天、同小区、同操作内容如果重复提交，很可能是误操作。

但农业现场也可能真的发生两次类似操作。

所以第一版应该做“软校验”：

> 系统提示疑似重复，让用户确认是否仍然保存。

这比直接禁止更合理。
