# Day 06 字段字典：育种基地观察记录模板

## 1. 使用场景

这份字段字典用于规范“育种基地多品种、多播期、多小区”的观察记录。

它不是完整产品，只是 Day 6 的数据入口练习。

真实业务里，用户经常会说：

> 我这里品种很多、播期很乱、生育期和农事操作都要记。

FDE 要做的第一步不是马上写页面，而是先问：

> 这些信息应该以什么字段进入系统？

## 2. 字段清单

| 字段名 | 中文含义 | 是否必填 | 示例 | 规则 |
|---|---|---:|---|---|
| `record_id` | 记录编号 | 是 | `R20260501001` | 同一份表内不能重复 |
| `variety_name` | 品种名称 | 是 | `稻香A` | 不能为空 |
| `sowing_batch` | 播期批次 | 是 | `第一播期` | 不能为空 |
| `plot_id` | 小区编号 | 是 | `A-01` | 不能为空 |
| `plot_area_mu` | 小区面积 | 是 | `0.08` | 必须是大于 0 的数字，单位：亩 |
| `event_date` | 观察或操作日期 | 是 | `2026-05-01` | 必须是 `YYYY-MM-DD` |
| `growth_stage` | 生育期阶段 | 是 | `播种` | 必须来自允许列表 |
| `farm_operation` | 农事操作 | 否 | `人工播种` | 可为空 |
| `operator` | 记录人 | 否 | `张三` | 可为空 |
| `note` | 备注 | 否 | `出苗整齐` | 可为空 |

## 3. 允许的生育期阶段

当前 Day 6 练习允许这些阶段：

```text
播种
出苗
分蘖
拔节
孕穗
抽穗
灌浆
成熟
收获
```

为什么要限制？

因为如果不同人随便写：

```text
抽穗
出穗
齐穗
抽穗期
```

后面做统计和提醒时就会很麻烦。

字段标准化，是 FDE 把现场混乱变成系统能力的第一步。

## 4. 日期格式

统一使用：

```text
YYYY-MM-DD
```

例如：

```text
2026-05-01
```

不要混用：

```text
2026/5/1
5月1日
2026.05.01
```

原因是：日期格式混乱后，程序很难稳定排序、筛选和计算提醒。

## 5. 当前明确不做

- 不计算积温；
- 不预测生育期；
- 不生成农事建议；
- 不判断品种表现优劣；
- 不替代育种人员的田间判断；
- 不做完整数据库，只做 CSV 模板校验。

## 6. 和 FDE 的关系

这份字段字典是典型的 FDE 工作：

```text
业务现场语言
→ 数据字段
→ 校验规则
→ 可交付模板
→ 后续产品功能
```

真正的交付不是“我写了代码”，而是让用户知道：

> 以后数据应该这样填，系统才可以稳定工作。
