# Day 08 需求假设：育种生育期进度看板

## 1. 背景

用户朋友做育种，基地面积不一定很大，但品种/材料多、播期复杂、生育期和农事日期需要持续记录。

朋友已经确认第一版最需要的是：

```text
品种 × 播期进度视图
```

也就是：

> 一眼看到每个品种/材料，在不同播期下分别走到哪个生育期。

## 2. 市面常见工作流参考

常见田间试验和育种管理系统通常会管理：

- 试验或圃；
- 材料/品种/组合；
- 小区 plot；
- 播种或移栽日期；
- 生育期或表型观察记录；
- 农事操作记录；
- 后续分析、报告或决策。

所以第一版不做“大而全系统”，而是先做最小看板：

```text
品种/材料
播期
小区
播种日期
最近观察日期
当前生育期
下一步观察事项
```

## 3. 四个问题的默认答案

### 3.1 一个材料一般几个播期？

默认 3 个：

- 第一播期；
- 第二播期；
- 第三播期。

这不是说真实基地一定只有 3 个，而是第一版产品用 3 个播期做演示最清楚。

### 3.2 播期怎么命名？

同时记录：

- `sowing_batch`：第一播期、第二播期、第三播期；
- `sowing_date`：实际播种日期。

前者便于人读，后者便于程序排序和计算。

### 3.3 生育期阶段有哪些？

第一版允许：

```text
播种
出苗
分蘖
拔节
孕穗
抽穗
灌浆
成熟
收获
```

### 3.4 是否显示下一步？

显示。

但第一版的“下一步”只是基于当前生育期的固定提醒，不是农艺建议。

例如：

```text
当前生育期：抽穗
下一步：拍照并记录抽穗整齐度
```

这不是说这个品种一定应该如何管理，只是提醒现场人员要继续观察什么。

## 4. 明确边界

第一版看板只做：

- 事实整理；
- 进度展示；
- 固定观察提醒。

不做：

- 品种好坏判断；
- 产量预测；
- 推广建议；
- 栽培管理建议；
- 病虫害诊断；
- 育种选择决策。

## 5. FDE 视角

这个 Day 8 练习非常典型：

```text
模糊需求
→ 合理假设
→ 最小可用看板
→ 拿给用户验证
→ 根据反馈修正字段和视图
```

这就是 FDE 做现场系统时常见的节奏。
