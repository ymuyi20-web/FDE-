# Day 11 田间录入规则说明

## 1. 这个模块解决什么问题

Day 8、Day 9、Day 10 都依赖数据。  
但真实项目里，最难的往往不是生成看板，而是：

> 一线人员愿不愿意、能不能轻松把数据录进去。

所以 Day 11 做一个田间手机录入表单原型。

## 2. 输入体验原则

### 原则一：少打字

能选择就不要手打。

适合做成选择项的字段：

- 品种/材料；
- 播期；
- 一级操作类型；
- 二级操作内容；
- 是否需要复查；
- 负责人。

### 原则二：默认值跟随上一条

田间人员常常连续录一批同一天、同一负责人、同一类操作。

所以默认逻辑应该是：

- 第一条记录日期默认今天；
- 用户提交后，下一条记录日期默认上一条记录日期；
- 用户提交后，下一条负责人默认上一条负责人；
- 用户可以随时手动修改默认值。

这比“每条都默认今天”更适合补录场景。

### 原则三：支持批量

同一操作可能同时发生在多个小区。

比如：

```text
A-01, B-01, C-01
```

如果用户一次填多个小区，系统应该自动生成多条记录。

### 原则四：记录事实，不做判断

可以写：

> 喷施防病药剂。

不建议写：

> 这个材料抗病性强。

前者是操作事实。  
后者是育种判断。

## 3. 第一版字段

| 字段 | 输入方式 | 默认逻辑 |
| --- | --- | --- |
| 日期 | 日期选择 | 第一条默认今天，之后默认上一条日期 |
| 材料 | 下拉选择，可选“其他”自定义 | 默认上一条材料 |
| 自定义材料 | 文本 | 选择“其他”材料时填写 |
| 播期 | 下拉选择，可选“其他”自定义 | 默认上一条播期 |
| 自定义播期 | 文本 | 选择“其他”播期时填写 |
| 小区 | 文本，可批量 | 支持逗号、空格、换行分隔 |
| 一级操作类型 | 按钮 | 默认上一条一级类型 |
| 二级操作内容 | 下拉选择 | 根据一级类型自动变化 |
| 自定义二级内容 | 文本 | 选择“其他”时填写 |
| 补充说明 | 文本 | 可填写药剂、用量、现场情况 |
| 负责人 | 下拉/文本 | 默认上一条负责人 |
| 是否复查 | 按钮 | 默认“否” |
| 备注 | 文本 | 可不填 |

## 4. 第一版操作类型

| 一级操作类型 | 二级操作内容 |
| --- | --- |
| 整地 | 翻耕、筑埂、上水、耖田、搅浆平杠、其他 |
| 播种 | 无人机飞播、机插秧、人工插秧、补秧、其他 |
| 施肥 | 底肥、分蘖肥、穗肥、追肥、叶面肥、其他 |
| 除草 | 封闭除草、茎叶除草、补打除草、人工除草、其他 |
| 植保 | 分蘖药、封行药、破口药、齐穗药、其他 |
| 晒田 | 晒田、复水、其他 |
| 灌溉 | 上水、排水、其他 |
| 巡田 | 苗情观察、分蘖观察、拔节观察、孕穗观察、抽穗观察、成熟观察、其他 |
| 拍照 | 生育期照片、病虫害照片、株型照片、异常照片、其他 |
| 测量 | 株高、分蘖数、剑叶角度、穗长、其他 |
| 其他 | 其他 |

## 5. 后续可以扩展

等朋友确认这个输入方式可接受后，可以继续加：

- 拍照上传；
- 语音备注；
- GPS 定位；
- 扫码识别小区牌；
- 离线保存；
- 多人同步；
- 数据导入 Day8、Day9、Day10 的看板。
